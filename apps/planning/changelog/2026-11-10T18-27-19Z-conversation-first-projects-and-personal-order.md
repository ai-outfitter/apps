# Project decisions, reports and personal order

Project pages lead with persisted intake/preparation questions, delivery blockers,
the saved calendar report and one action to continue the existing project
conversation. Reports use the persisted schedule calendar and link their exact
Wiki revision. Missing/incomplete reads remain explicit. Existing documents,
issues and maintenance controls remain under native details; deep routes remain
available. The redundant Product and empty Operations sidebar links are removed.

Personal project directories add organization and project drag handles through
the existing PersonalPortfolio/ReorderPersonalPortfolio documents. Ordering stays
private, retains unseen authorized records, checks revisions and preserves
organization membership. Keyboard movement uses the same handles; there are no
new arrow buttons.

Validated with focused presentation tests, package type/build checks and
representative desktop/mobile browser journeys. Isolated local development served
on port 4497; its legacy seeded personal project context returned 503, so live
project-thread restoration was not confirmed there. Fixture browser results do
not imply provider or production activation. Screenshot artifacts stay outside Git.
